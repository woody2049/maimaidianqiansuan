# 示例 3：外送 + 均衡 + 忌口，金额和配送费一起算

**用户说**：「今晚外送，预算 60，要巨无霸，不吃苹果片，均衡一点，周二。」

## 输入

```json
{
  "budget": 60,
  "nutrition": "balanced",
  "pickup": "delivery",
  "want": ["bigmac"],
  "avoid": ["apple"],
  "coupon": "prefer",
  "store": { "delta": 0, "soldout": [] },
  "weekday": 2
}
```

## 命令

```bash
python3 scripts/meal_planner.py --budget 60 --nutrition balanced --pickup delivery \
    --want bigmac --avoid apple --coupon prefer --weekday 2
```

## 输出

```text
## 条件
- 预算：¥60｜营养参考：均衡｜取餐方式：外送
- 必吃：巨无霸｜忌口：苹果片｜券偏好：优先用券
- 门店：差价 +0.0｜停售：无｜可选 26 件

## 筛选过程
穷举 209 种组合 → 预算内 192 种 → 同时达到营养参考 45 种（候选池）

- 配送费：¥6（券后未满 ¥39）
- 餐品：巨无霸 ¥25.5、香芋派 ¥9
```

## 规则怎么落地的

- **渠道先筛**：外送不售沙拉与全部冰淇淋类（易融化/不便配送），可选从 30 件降到 26 件；苹果片被忌口剔除。这两步都发生在穷举之前，所以组合数只有 209 种，而不是先算 4000 种再过滤。
- **预算比较的是含运费实付**：预算优先组 34.5 元券后 29.5，没到 39 的免运线，要加 6 元配送费，实付 35.5。货架价 34.5 看着最便宜，付的钱不是。
- **营养优先组** 685 千卡 / 30g 蛋白，正好落在均衡区间（450–900），脂肪与钠也是三组最低。
- **口味优先组**用随心配把「麦乐鸡 5 块 + 柠檬茶」（14.5 + 13 = 27.5）改价到 13.9，省 13.6；900 千卡刚好踩在均衡上限，**再多一件就出区间**——这就是硬门槛和「差不多」的区别。
- **「周二会员日 88 折」在这单里没被选中**：三组总价的 12% 分别是 4.14 / 5.64 / 6.36，都低于对应的固定金额券（5 / 8 / 13.6）。券是按**实际省多少**比出来的，不是按面额或类型。

## 读这一例该注意

三个应付（35.5 / 39 / 39.4）都在预算 60 内，但排序完全不同：如果按总价排，预算优先组领先；如果按实付排，营养优先组几乎追平。**外送场景下，运费会把「最便宜」和「实付最低」拆成两件事**。
