# 示例 2：预算太紧 + 高蛋白，直接判无解

**用户说**：「25 块钱，双层吉士汉堡，要高蛋白。」

## 输入

```json
{
  "budget": 25,
  "nutrition": "protein",
  "pickup": "pickup",
  "want": ["doublech"],
  "avoid": [],
  "coupon": "normal",
  "store": { "delta": 0, "soldout": [] },
  "weekday": 1
}
```

## 命令

```bash
python3 scripts/meal_planner.py --budget 25 --nutrition protein --pickup pickup \
    --want doublech --coupon normal --weekday 1
```

## 输出

```text
## 条件
- 预算：¥25｜营养参考：高蛋白｜取餐方式：到店自取
- 必吃：双层吉士汉堡｜忌口：无｜券偏好：顺其自然
- 门店：差价 +0.0｜停售：无｜可选 30 件

## 筛选过程
穷举 539 种组合 → 预算内 4 种 → 同时达到营养参考 0 种（候选池）

## 无解诊断
- **【营养】「高蛋白」和预算互相打架**：预算内蛋白质最高 31g，离目标 42g 差 11g。 达标最便宜的组合要 ¥33.4。

## 可放开的条件（每个都先试算确认有解）
- 增加预算：¥25 → ¥34，能满足全部条件
- 放宽营养参考：高蛋白 → 均衡
- 替换餐品：把「双层吉士汉堡」换成「吉士汉堡」（¥13.5），营养放宽到均衡
- 去掉一个餐品：去掉「双层吉士汉堡」，营养放宽到均衡
- 更换取餐方式：另外两种方式也凑不出来
- 更换门店：换门店也解决不了
```

## 规则怎么落地的

- 预算内只有 4 种组合，蛋白质最高 31g，达不到 42g 的硬门槛 → **候选池为空 → 判无解，不出方案卡**。这里没有「尽力而为」的选项，也不拿超预算的搭配充数。
- 诊断分两步：先算**差多少**（差 11g 蛋白），再算**达标最便宜要多少**（¥33.4），所以「加预算到 ¥34」是第一个建议，数字有依据。
- **放宽营养到均衡**是第二优先：均衡的通过条件是 450–900 千卡，比「蛋白 ≥ 42g」容易满足。
- **换渠道、换门店标「凑不出来 / 解决不了」**：它们改变不了蛋白质总量，明确 disabled，不让用户白点——这比给六个都能点的按钮更诚实。

## 读这一例该注意

无解不是失败，是信息。用户真正需要知道的是「25 块买不到 42g 蛋白，最少要 34 块」，而不是「给你一个 31g 蛋白的方案，反正差不多」。

如果要写前端，判断条件很直接：候选池长度 0 → 渲染诊断面板 + 禁用「换一组 / 保存 / 去点餐」，别让用户对着空列表点。
